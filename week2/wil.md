화면이 더 복잡해진다면..?

조금 더 만들어볼까요? 좋아요 하나에서 게시글 하나로 확장

게시글 하나의 구성요소(사용자 이름, 프로필 이미지, 게시물 이미지, 이미지 슬라이드, 좋아요 버튼, 댓글 버튼, DM버튼, 본문, 등등...)

React가 없어도 JS만으로도 가능. But, 우리가 지금 만들고 있는 건 뭘까? -> **화면!**

**화면을 보면 구조가 보인다!** (profile, image, action, content)

화면을 조금 더 화면답게 표현한다면? **코드에서도 화면의 구조가 보인다면?**

* ###### React : UI를 만들기 위한 JavaScript Library (!= Programming Language) JS에서 사용하는 도구. React + JS = UI
* ###### Library : 필요한 것을 찾아서 활용한다 (요리가 궁금하다 -> 도서관 -> 요리책) 다른 프로그램에서 가져다 사용할 수 있도록 만들어놓은 코드의 모음. (필요한 코드가 있다 -> 가져와서 사용한다 -> 내 프로그램을 만든다)

개발할 때도 모든 코드를 처음부터 만들 필요는 없음. 이미 누군가가 만들어놓은 좋은 코드를 찾아서 사용함.

우리가 오늘 필요한 것? UI!

JavaScript + React -> UI

즉, React는 UI를 만들기 위한 JS Library다!



JS에서는 화면의 요소를 찾고, 동작을 연결했다.

필요한 요소를 찾아 하나씩 다룸.

##### React 구조

##### >	<	>

##### &#x09;{	}

JS에서보다 React에서 화면의 구조가 더 직관적으로 보임.

React를 사용한다고 코드의 길이가 짧아진다는게 아님.

* ###### JSX : JS 안에서 UI를 표현하기 위한 문법. (HTML과 비슷하게 생김)

게시글마다 구조는 비슷하지만 값은 다름.

횟집의 "싯가"

const fish = "대방어";	->	<h2>{fish}</h2>

const price = 70000;			<p>{price}원</p>

* ###### { } : JavaScript 값을 JSX에서 사용하는 자리. { } 안에서는 JS 표현식 사용 가능. (python에서 f-string 같은 개념)

개발자는 데이터를 다루고, 사용자는 정보를 봄.

숫자가 의미하는 바가 뭔지, 8888? 좋아요 수! false보단 품절이라는 단어로 표현

**프론트앤드는 단순하게 데이터를 화면에 출력만 하는게 아니라, 그 데이터가 사용자에게 어떤 의미로 보여야 하는지 생각해야함!**



화면을 화면답게!

JSX : UI의 구조를 표현

Data : 화면에 보여줄 값

{ } : JS와 JSX를 연결

좋은 UI를 만들려면, 먼저 "**화면**"을 볼 수 있어야 함!

잘 만들려면, 잘 설명할 수 있어야 함.

무엇을 원하는지 결과만 말하는 것보단, 화면의 "**구조**"와 "**역할**"을 설명해야 AI도 효율적으로 사용 가능.

화면을 보는 눈이 코드를 배우는 것만큼 중요함.



JavaScript -> React -> JSX -> 직접 화면 만들기
